# kondooit-runtime

Browser WASM runtime for Kondooit — establishes iroh tunnel connections from the browser to a Kondooit server sidecar.

## What is this?

This is a Rust crate compiled to WebAssembly that runs in the browser. It creates an [iroh](https://iroh.computer) endpoint and connects to a remote Kondooit server over iroh's relay network. All connections are **end-to-end encrypted**.

The browser runtime is loaded when a user visits their Kondooit URL. The page URL contains a bootstrap payload (base64url-encoded JSON in the URL fragment) that tells the runtime which server to connect to.

### How it works

1. **Page loads** → WASM module is fetched and initialized
2. **Endpoint created** → An iroh endpoint is spawned in the browser (relay-only, since browsers can't open UDP sockets)
3. **Bootstrap payload parsed** → The URL fragment `#<base64url-json>` is decoded to extract the server's endpoint ID
4. **Connection established** → The browser connects to the server's iroh sidecar using the `kondooit/tunnel/0` ALPN protocol
5. **Tunnel active** → HTTP requests are tunneled over iroh's encrypted bidi streams

### Bootstrap payload format

The URL fragment contains a base64url-encoded JSON object:

```
https://app.kondooit.com/t/my-site#eyJ2IjoxLCJlbmRwb2ludF9pZCI6ImFiY2RlZjEyMzQ1NiJ9
```

Decoded payload:
```json
{
  "v": 1,
  "endpoint_id": "abcdef123456..."
}
```

- `v` — payload version (currently `1`)
- `endpoint_id` — the server sidecar's iroh endpoint ID (hex-encoded public key)

## Prerequisites

- [Rust](https://rustup.rs/) (stable)
- `wasm32-unknown-unknown` target: `rustup target add wasm32-unknown-unknown`
- `wasm-bindgen-cli` **v0.2.126** (must match the pinned crate version exactly):
  ```
  cargo install wasm-bindgen-cli@0.2.126
  ```

## Build

```bash
# Full build: compile Rust to WASM + generate JS bindings
npm run build

# Or step by step:
cargo build --target wasm32-unknown-unknown --release
wasm-bindgen target/wasm32-unknown-unknown/release/kondooit_runtime.wasm \
  --out-dir public/wasm --target web --no-typescript
```

The build outputs go into `public/wasm/`:
- `kondooit_runtime.js` — ES module that loads the WASM
- `kondooit_runtime_bg.wasm` — the compiled WebAssembly binary

## Serve locally

```bash
npm run serve
# → http://localhost:8080
```

To test with a bootstrap payload, append a fragment:

```bash
# Create a test payload
echo -n '{"v":1,"endpoint_id":"your-server-endpoint-id-here"}' | base64 | tr '+/' '-_' | tr -d '='

# Visit: http://localhost:8080/#<encoded-payload>
```

## Limitations

- **Relay-only**: Browsers cannot open raw UDP/QUIC sockets, so all connections flow through an iroh relay server. The relay cannot decrypt traffic (end-to-end encryption).
- **No direct connections**: Hole-punching is not available in the browser sandbox. Future support for WebTransport or WebRTC may enable direct connections.
- **WASM size**: The release build with `opt-level = "s"`, LTO, and symbol stripping produces a reasonably small binary, but it's still a full iroh endpoint.

## Protocol

The `kondooit/tunnel/0` ALPN protocol is used for all connections. This MUST match the server sidecar's ALPN exactly. The protocol is a simple bidirectional stream:

**MVP (PING):**
- Client opens a bidi stream
- Client writes `PING\n` and finishes the send side
- Server responds with `PONG\n` and finishes its send side

**Future (HTTP tunneling):**
- Client opens a bidi stream per HTTP request
- Client writes serialized HTTP request
- Server proxies to the local service, writes back the HTTP response
